# ADR-0002: Ядро в статической библиотеке

## Статус

Принято.

## Контекст

В upstream всё собиралось одним `add_executable`, и протестировать класс можно
было, только запустив приложение целиком. Тестов не было.

## Решение

Всё, кроме `main.cpp`, собирается в статическую библиотеку `morph_core`.
Приложение это `main.cpp`, ресурсы и `morph_core`. Каждый тест отдельный
бинарник, который линкует ту же библиотеку.

Сетевые сервисы тестируются против локального `FakeHttpServer`, адрес API
подменяется переменными `MORPH_YANDEX_API` и `MORPH_SOUNDCLOUD_API`. Внешние
программы (yt-dlp) подменяются скриптами.

Попутно номер сборки берётся из `git rev-list --count HEAD`: раньше configure
дописывал его в `build_number.txt`, и после любой сборки дерево было грязным.

## Последствия

- Тесты проверяют настоящие запросы (пути, тела, заголовки) без доступа к
  Яндексу и SoundCloud.
- Классы, завязанные на плеер, лучше делать независимыми от него
  (`ListenTracker` получает состояние слотами, а не берёт `AudioEngine`).
