# ADR-0022: Окно не ждёт

## Статус

Принято.

## Контекст

Окно подвисало на старте и при смене трека. В плане этот этап был записан как
«вся работа в отдельном сервере, окно только показывает». У окна десятки
прямых вызовов с мгновенным ответом, и перенос их за межпроцессный канал это
недели работы с риском сломать то, что работает. Синхронных ожиданий в коде
нет, значит, окно ждёт тяжёлую работу на главном потоке. Её и надо найти.

Замер на стенде реального размера (год прослушиваний, 20 тысяч событий, карта
из 1900 артистов, 1500 лайков), отладочная сборка:

| что | было | стало |
|---|---|---|
| пересборка карты, на главном потоке | 604 мс | 38 мс |
| лайк | пересчёт всей истории | 36 мс |
| карта целиком (в фоне) | 816 мс | 71 мс в RelWithDebInfo |
| загрузка истории на старте | 315 мс | 203 мс в RelWithDebInfo |

Пересборка карты шла после каждого дослушанного трека, который принёс новых
соседей по Last.fm: окно замирало на полсекунды рядом со сменой трека.

## Решение

- **Вкус по всей истории считается в фоне** вместе с картой. В поток уходят
  снимки графа, базы знаний и истории: копии общие с оригиналами, пока те не
  поменяются, снимок почти ничего не стоит. Обратно приходят векторы всех песен
  и готовый вкус; то, что пришло за время расчёта, досчитывается на месте.
- **Лайк меняет только слагаемое лайков**, а не пересчитывает историю.
- **`make` собирает RelWithDebInfo**: с оптимизацией и с отладочными символами.
  В Debug наш код в разы медленнее, а для повседневного запуска это лишняя
  нагрузка. Отладка: `make build BUILD_TYPE=Debug`.
- **Предзагрузка на два трека вперёд**: трек с YouTube ищется yt-dlp секунды,
  и если пролистать следующий, за ним уже ждёт готовый.
- **Сторож главного потока** пишет в `stalls.log` время старта по частям и
  каждую паузу окна длиннее 250 мс вместе с отмеченными операциями, которые в
  неё попали. Так видно, что тормозит на настоящих данных, а не на стенде.

Фоновый сервер уже есть (ADR-0019): `morph --server` в автозапуске раздаёт
библиотеку телефону, строит миксы, слушает кэш и учится у Last.fm, пока окно
закрыто. Окно при запуске забирает у него данные, при закрытии отдаёт.

## Последствия

- Первая сборка после обновления пересобирает всё: сменился тип сборки.
- Паузы, которые сторож пометит как «unmarked (QML or Qt)», идут из интерфейса;
  их ищем по журналу, когда они появятся.
