# ADR-0003: Моя волна через rotor-сессии

## Статус

Принято.

## Контекст

Upstream брал волну из `GET /rotor/station/user:onyourwave/tracks` и никак не
сообщал, что с треками стало дальше. Статистика уходила в момент старта:
длина 180 секунд, прослушано 0, вместо id альбома его название. Для
рекомендаций это выглядело как бесконечные старты без единого дослушанного
трека.

Нынешние клиенты Яндекса слушают волну через сессии: `rotor/session/new`
выдаёт партию треков, `rotor/session/{id}/feedback` принимает события.

## Решение

- Волна создаёт сессию и шлёт `radioStarted`, дальше на каждый трек из неё
  `trackStarted` и в конце `skip` или `trackFinished` с реально прослушанными
  секундами. Лайк и дизлайк трека из волны тоже уходят событием.
- Следующая партия берётся из той же сессии с `queue` уже выданных треков.
  Протухшая сессия (`unknownSession`) пересоздаётся.
- Если сессию создать не удалось, остаётся старая станция, без фидбека.
- `play-audio` уходит один раз, когда трек закончился или пропущен, с
  настоящими секундами. Время считает `ListenTracker` без пауз.

## Последствия

- Волна получает те же сигналы, что от официального клиента, и учится на
  скипах и дослушиваниях.
- API неофициальное. Если Яндекс его поменяет, сломается фидбек, но не
  воспроизведение: станция остаётся запасным путём.
